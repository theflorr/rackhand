# Cisco FTD (Firepower Threat Defense / Secure Firewall) CLI Reference

## 1. Operating System & Platform Architecture

### Overview
Cisco Firepower Threat Defense (FTD), rebranded as **Cisco Secure Firewall**, is Cisco's unified Next-Generation Firewall (NGFW) operating system. FTD merges two foundational engines on top of an underlying Linux / FXOS architecture:
* **Lina Engine (ASA Data-Plane):** Handles TCP/UDP stateful inspection, IP routing, NAT, connection tracking, VPN termination, and Layer 2/3/4 operations.
* **Snort Engine (Snort 2 / Snort 3):** Deep Packet Inspection (DPI), Application Visibility & Control (AVC), Snort IPS signatures, File Policy, TLS decryption, and URL filtering.
* **Management Paradigm:** FTD is designed to be managed declaratively by **Cisco Firepower Management Center (FMC)** or locally via **Firepower Device Manager (FDM)**. 

> [!WARNING]
> FTD CLI is fundamentally an **operational, monitoring, and diagnostic environment**, not a manual configuration environment. Directly entering configuration mode in the underlying Lina CLI is ephemeral and will be overwritten or cause sync errors during the next FMC policy deployment!

### Target Platforms & Hardware
* **Hardware Appliances:** Cisco Secure Firewall 1000 Series (1010, 1120, 1140, 1150), 2100 Series, 3100 Series (3105, 3110, 3120, 3130, 3140), 4100 Series, and 9300 Modular Chassis.
* **Virtual Appliances:** Cisco Secure Firewall Threat Defense Virtual (FTDv) for AWS, Azure, GCP, VMware ESXi, KVM.

## 2. CLI Modes, Architecture & Shell Navigation

FTD features three distinct CLI tiers accessible from a single console session:

```
FTD CLISH Shell (>)
  │
  ├── 1. Diagnostic / Lina Engine CLI (system support diagnostic-cli -> #)
  │      └── Full Cisco ASA show, packet-tracer, and capture syntax
  │
  ├── 2. Linux Expert Shell (expert -> admin@firepower:~$)
  │      └── Full Linux Bash environment (pmtool, snort logs, disk, systemd)
  │
  └── 3. FXOS Chassis Shell (Modular 4100/9300 appliances)
         └── Chassis fabric, power, and physical module supervisor
```

### Prompt Patterns & Regex Matching
| Mode | Standard Prompt | Regex Pattern |
|---|---|---|
| **FTD CLISH** | `> ` or `firepower> ` | `^[A-Za-z0-9_\-\.\/]*>\s*$` |
| **Diagnostic (Lina)**| `firepower# ` | `^[A-Za-z0-9_\-\.\/]+#\s*$` |
| **Linux Expert** | `admin@firepower:~$ ` | `^[A-Za-z0-9_\-]+@[A-Za-z0-9_\-]+:.*[\$#]\s*$` |
| **FXOS Shell** | `firepower-4100# ` | `^[A-Za-z0-9_\-]+#\s*$` |

### Transitions Between Shells
* **CLISH -> Diagnostic (Lina) CLI:**
  ```bash
  > system support diagnostic-cli
  firepower# 
  ```
  *(Return to CLISH: `exit`)*
* **CLISH -> Linux Expert (Bash) Shell:**
  ```bash
  > expert
  admin@firepower:~$ 
  ```
  *(Gain root privileges: `sudo su`)*
  *(Return to CLISH: `exit`)*

## 3. Terminal Control & Output Formatting

Inside FTD CLISH:
```bash
! CLISH pagination control (pipe or direct)
show version
```
Inside the Diagnostic (Lina) CLI:
```cisco
! Disable pagination (ASA syntax)
terminal pager 0
```

## 4. Comprehensive CLI Command Reference

### A. FTD CLISH: Platform, System & Management Status
```bash
! System release, Snort build, uptime, Lina engine build
show version

! Management network interface IP, gateway, and DNS configuration
show network

! Management registration status (Connected to FMC / Security Cloud Control)
show managers

! Real-time traffic throughput and packet rate across interfaces
show traffic

! Snort inspection performance status (CPU, memory, packet queue)
show performance status

! Snort 3 engine active statistics and counters
show snort3 counters
show snort3 statistics

! Failover / HA status
show failover
```

### B. Diagnostic (Lina) CLI: Flow Inspection & Packet Tracing
Accessed via `system support diagnostic-cli`:

```cisco
! Interface IP mapping and link state
show interface ip brief

! Active stateful connection table
show conn
show conn detail
show conn count

! Active NAT translations
show xlate

! Configured NAT rules and hit counters
show nat

! Accelerated Security Path (ASP) drop counters
show asp drop

! Access lists generated by FMC policy deployment
show access-list

! Packet-Tracer simulation through both Lina and Snort DAQ
packet-tracer input inside tcp 192.168.1.100 54321 8.8.8.8 443 detailed
```

### C. Live Snort & Firewall Engine Debugging
Inside FTD CLISH:

```bash
! Real-time trace of rule evaluations, Snort verdicts, and security policy matching
system support firewall-engine-debug

! Real-time packet sniffer directly on the data-plane
system support capture-traffic
```

### D. Linux Expert Shell: Deep System & Daemon Maintenance
Accessed via `expert`:

```bash
# Check status of core FTD processes via Process Manager Tool (pmtool)
pmtool status
pmtool status | grep -E "(Snort|Lina|Disk|Action Queue)"

# Restart Snort process independently
sudo pmtool restartbyid snort

# Monitor Snort alert and diagnostic logs
sudo tail -f /var/log/messages
sudo tail -f /ngfw/var/log/snort/snort.log

# Check disk space utilization across partitions (/ngfw, /var)
df -h
```

### E. File System, Maintenance & Factory Reset
```bash
! Restart the FTD software services
reboot

! Generate a comprehensive system support bundle for TAC
system support platform-dump

! View crash dumps and core files
system support view-files
```

## 5. Error Indicators & Parsing Gotchas

| Error Pattern | Cause | Meaning / Action |
|---|---|---|
| `Command rejected: Not supported in this shell` | Mode confusion | Command was typed in CLISH instead of `diagnostic-cli`. |
| `Cannot connect to Lina engine` | Process crash | The underlying Lina data-plane process is restarting. |
| `Snort down / bypassing traffic` | Engine fault | Snort memory exhaustion or crash; inspect `pmtool status`. |
| `FMC Registration: Not Connected` | Mgmt isolation | FTD cannot reach FMC over TCP 8305 (sftunnel). |

### Parsing Traps on FTD
1. **Multi-Layered Output Formats:** Always confirm which shell prompt you are in before parsing (`>` for CLISH, `#` for diagnostic Lina, `$` for expert bash).
2. **Read-Only Mentality:** Do not attempt to script configuration changes in `diagnostic-cli`; FMC policy pushes will wipe them out.
3. **`packet-tracer` Integration:** On FTD, `packet-tracer` output includes both `PHASE: ACCESS-LIST` and `PHASE: SNORT`, showing whether Snort evaluated or bypassed the packet.
